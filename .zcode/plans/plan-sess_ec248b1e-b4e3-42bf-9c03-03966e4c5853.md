# 可切换数据源存储:SQLite(默认)/ MySQL — 实施计划

## 勘察结论(已确认的事实)

- 现状:better-sqlite3 同步驱动,`.all()` 169 处 / `.run()` 113 处 / `.all()[0]` 76 处 / `.changes` 7 处,分布在约 120 个文件——这是**全库最大的驱动耦合面**
- MySQL 驱动(mysql2)**没有 `.all()/.run()` 方法**,只有 then-able 的 `execute()`;`.changes` 也不存在(mysql 返回 `[result, fields]`)
- Drizzle 0.45.2 已内置 `mysql-core` + `mysql2` 驱动 + MySQL migrator,无需升级
- schema 只用 5 种 sqlite-core 类型;11 个 `integer({mode:"boolean"})` 需映射为 mysql `boolean()`;时间戳全是 text 存 UTC-ISO(MySQL 侧保持 text 列即可跨库一致)
- backup.ts 依赖 SQLite 原生 backup API → MySQL 模式下快照功能需禁用并提示
- settings KV 表天然适合存切换配置;`.env` 存 `DATABASE_URL`(用户已确认:环境变量切换、自动建表、要迁移工具、配置放 .env)

## 实施方案(完整双方言支持)

### Task 1: 双 Schema 与迁移体系
- `src/lib/db/schema.ts` 保持不变(SQLite 主 schema)
- 新建 `src/lib/db/schema-mysql.ts`:与 sqlite schema **表/列一一对应**的 mysql-core 版本(`mysqlTable`、`boolean()` 替代 `integer({mode:"boolean"})`、`index()` 同构)
- 新建 `drizzle-mysql.config.ts`(dialect: "mysql", schema 指向 schema-mysql.ts, out: `./drizzle-mysql`)
- 运行 `drizzle-kit generate` 生成 MySQL DDL;首次连接时由迁移器自动执行(建库+建表)
- package.json 增加 `"db:generate:mysql"` 脚本

### Task 2: 连接层抽象(client.ts 改造,保持 123 处调用兼容)
- `getDb()` 读取 `DATABASE_URL`:
  - 未设置(默认)→ 现有 SQLite 路径,行为完全不变(同步)
  - `mysql://...` → mysql2 连接池 + drizzle mysql,自动执行 MySQL 迁移 + seed
- 导出 `dbDialect(): "sqlite" | "mysql"` 供各处判断
- `Db` 类型放宽为 union;新增 `type DbKind` 判别
- **MySQL 模式约束**:backup 快照/恢复 API 返回 501 并提示"MySQL 模式不支持文件快照"(其他功能全部可用)

### Task 3: 调用点 await 化 + 方法统一(~120 文件,机械改造)
- `.run()` → `await`(then-able 自动适配两方言;SQLite 下 await 同步结果无损)
- `.all()` → `await`;MySQL 下改为 `.execute()`?——**不需要**:`MySqlSelectBase` 是 QueryPromise,直接 `await builder` 即可;但 `.all()` 方法名不存在 → 用 sed 批量改 `.all()` → await + 删 `.all()`,即 `await db.select()...`
  - SQLite: `await select()` 等价 `.all()`(drizzle SQLite select 也是 QueryPromise)
  - MySQL: `await select()` 即 execute
- `.all()[0]` → `(await ...)[0]`
- `.changes` → 统一封装 `rowCount(result)` 帮助函数(SQLite 取 `.changes`,MySQL 取 `[0].affectedRows`),7 处调用点替换
- 2 处 `db.transaction` 保留(两方言 API 同名,mysql 侧回调需 async——runner.ts 内同步 insert 需 await 化)
- 每文件改造后 tsc 通过即验证;分批提交(business domain → api routes → pages)

### Task 4: 测试适配
- `createTestDb()` 保持 SQLite 内存库(测试永远跑 SQLite,快且稳定)
- client.test.ts 增加 MySQL 连接解析分支的单元测试(mock mysql2)

### Task 5: SQLite → MySQL 一次性迁移工具
- 设置页新增「数据迁移(SQLite → MySQL)」卡(仅 MySQL 模式显示):
  - 上传/指定本地 SQLite 文件路径 → 逐表读 SQLite 全量 → 批量 insert MySQL(27 表按外键顺序)→ 可选"清空目标表"
  - 完成后显示逐表行数对比
- API: `POST /api/db/migrate-from-sqlite {sqlitePath, truncate?}`

### Task 6: 文档与验证
- README:数据库配置说明(默认 SQLite 零配置;`DATABASE_URL=mysql://...` 切 MySQL;迁移工具用法)
- 全量验证:`npx vitest run`(433+ 用例,SQLite)→ `npm run build` → **真实 MySQL 实测**(连接本地/远程 MySQL → 自动建表 → 迁移工具导数 → 抽查页面/对话/任务链路)
- 提交推送 Gitee + GitHub develop

## 关键风险与对策
- **风险**:283 处 await 化遗漏导致 MySQL 下静默丢写 → 对策:tsc 严格模式下 mysql `Db` 类型不带同步 `.run()/.all()`,漏改处**编译期报错**,不会带病上线
- **风险**:时间戳 text 列在 MySQL 排序/比较 → 保持 text 列(ISO 字符串字典序=时间序),不换 datetime,行为跨库一致
- **兼容性**:默认不设 `DATABASE_URL` 时一切照旧,现有用户零感知
